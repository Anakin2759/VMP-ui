# VMP-ui 设计构想

## 1. 产品定位

VMP-ui 的目标是构建一个基于 EnTT 的轻量级 UI 框架：

- 以 ECS 作为 UI 实体和组件的基础模型；
- 以事件循环作为主要调度中心；
- 支持跨线程提交事件和任务，同时保证 UI 状态只在受控线程中修改；
- 提供接近 Qt 使用体验的基础控件和事件模型；
- 提供类似 Qt Quick 的锚点布局能力，用于表达组件之间的几何关系。

框架应优先保持核心机制简单、边界清晰和可测试，避免为了扩展性过早引入复杂的通用框架。

## 2. 核心架构

### 2.1 ECS UI 模型

UI 元素建模为 EnTT Entity，行为和状态拆分到独立组件中，例如：

- 几何组件：位置、尺寸、边界和变换；
- 层级组件：父子关系、显示顺序和窗口归属；
- 状态组件：可见性、启用状态、焦点和交互状态；
- 样式组件：颜色、字体、边距、圆角和主题属性；
- 事件组件：点击、键盘、鼠标、拖拽和文本输入回调；
- 布局组件：尺寸约束、锚点关系和布局策略。

组件只保存数据，不承载复杂行为。布局、输入、动画、渲染等行为由独立 System 处理。

### 2.2 事件循环

事件循环是框架的主要调度入口，负责：

1. 接收原生窗口事件和输入事件；
2. 接收其他线程投递的 UI 任务；
3. 按阶段驱动输入、业务逻辑、布局、动画和渲染；
4. 在安全的 UI 执行上下文中修改 Registry；
5. 管理退出、唤醒、队列满和任务异常等生命周期状态。

建议采用“多生产者、单 UI 消费者”的模型：

- 任意工作线程可以投递任务或事件；
- UI Registry、布局状态和渲染状态默认只由 UI 线程访问；
- 跨线程调用不直接修改 UI 组件，而是转换为可排队的命令或任务；
- 事件循环需要具备明确的线程归属、关闭协议和投递失败语义。

这样既能兼容多线程事件调度，也能避免为整个 ECS 状态引入高成本的全局锁。

## 3. 布局系统

### 3.1 锚点属性

布局系统应提供类似 Qt Quick anchors 的属性，用于描述组件之间的相对几何关系，例如：

- `left`、`right`、`top`、`bottom`；
- `horizontalCenter`、`verticalCenter`；
- `fill`：填充目标组件；
- `centerIn`：在目标组件内部居中；
- 锚点边距和偏移量；
- 最小尺寸、首选尺寸和最大尺寸。

典型关系包括：

```text
标题.bottom = 工具栏.top - 间距
内容.left   = 父容器.left + 边距
内容.right  = 父容器.right - 边距
按钮.center = 对话框.center
```

### 3.2 锚点约束规则

锚点系统需要明确以下规则：

- 同一方向不能同时存在互相冲突的约束；
- `fill`、`centerIn` 与显式边锚点之间要有优先级或互斥规则；
- 锚点关系不能形成循环依赖；
- 锚点目标被销毁时，关系应自动失效或返回可诊断错误；
- 布局求解失败时不能产生未定义几何值；
- 布局更新应支持脏标记，只重新计算受影响的子树。

### 3.3 布局求解阶段

建议将布局处理拆为以下阶段：

1. 收集组件的尺寸约束和锚点关系；
2. 构建局部依赖图并检测循环；
3. 计算父子容器和锚点目标的几何关系；
4. 应用最小、首选、最大尺寸约束；
5. 更新布局结果并产生渲染脏标记；
6. 将布局变更通知命中测试和渲染系统。

锚点系统与 Flexbox、Grid 等布局策略应作为互补能力，而不是相互覆盖。建议先实现稳定的锚点子集，再逐步扩展复杂布局策略。

## 4. 控件与 Qt 风格 API

基础控件可以参考 Qt 的分类和使用体验，但不直接复制 Qt 的实现细节或 API 设计。优先覆盖：

- `Window`、`Dialog`、`Popup`；
- `Button`、`CheckBox`、`RadioButton`、`Switch`；
- `Label`、`LineEdit`、`TextEdit`；
- `ListView`、`TableView`、`ScrollView`；
- `Slider`、`ProgressBar`、`ComboBox`；
- 菜单、工具栏、状态栏和上下文菜单。

控件应尽量由以下部分组合而成：

- 数据组件；
- 交互状态；
- 布局属性；
- 样式和主题属性；
- Renderer；
- System 注册的事件处理器。

避免为每个控件建立庞大的继承层次。控件差异优先通过组件、策略和组合实现。

## 5. 多线程事件调度边界

### 允许跨线程执行的操作

- 投递 UI 命令；
- 请求创建、销毁或更新 UI 元素；
- 发送业务事件；
- 请求资源加载并在 UI 线程提交结果；
- 请求刷新、重排或退出。

### 默认禁止的操作

- 工作线程直接读写 UI Registry；
- 工作线程直接修改布局组件；
- 工作线程直接调用 Renderer 或 GPU 资源接口；
- 在任意线程直接触发只能由 UI 线程消费的回调。

如果确实需要读取 UI 状态，应提供快照或显式同步查询接口，而不是暴露 Registry 的全局锁。

## 6. 设计优先级

建议按以下顺序推进：

1. 稳定 Runtime、Registry 和事件循环的生命周期与线程契约；
2. 完成基础实体、父子层级和可见性模型；
3. 实现最小可用的锚点布局系统；
4. 建立输入、布局、渲染的固定帧阶段；
5. 实现 Button、Label、Window、Dialog 等基础控件；
6. 增加主题、动画、文本输入和复杂列表控件；
7. 最后扩展 Grid、复杂约束和更高级的 Qt Quick 风格能力。

## 7. 关键设计原则

- **简单优先**：先实现少量稳定机制，不提前建设通用插件平台。
- **线程边界明确**：跨线程只传递任务、命令或不可变数据。
- **数据与行为分离**：组件保存状态，System 执行行为。
- **错误可诊断**：布局失败、投递失败、无效实体和生命周期错误必须有明确结果。
- **增量更新**：布局、命中测试和渲染都应以脏标记控制工作范围。
- **可测试性优先**：布局求解、事件顺序、线程投递和控件状态机都应可脱离真实窗口进行测试。
- **Qt 风格而非 Qt 复制**：借鉴成熟的控件语义和使用体验，但保持 VMP-ui 自身的 ECS 和生命周期模型。
